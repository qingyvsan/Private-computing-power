## 一、项目总览

私域算力集群，将家庭/个人闲置算力（CPU/GPU/内存/磁盘）汇聚成统一的、自主可控的计算集群。已确认 **8 个核心技术方向** 与 **1 个远期方向**：

| # | 方向 | 状态 |
|---|------|------|
| 1 | HAMi Standalone 模式 GPU 共享 | ✅ P5 |
| 2 | 分层客户端打包（core / runtime / GPU 层） | ⬜ P10 |
| 3 | WAL + rsync 双节点热备 | ⬜ P8 |
| 4 | Nebula Overlay 网络 | ✅ P6 |
| 5 | 信任图可见性控制 | ⬜ P7 |
| 6 | NAT 穿透（Lighthouse + STUN） | ✅ P6 |
| 7 | 邀请制私域接入（邀请码 + 管理员密钥） | ⬜ P9 |
| 8 | 用户主机 Web 控制台（双击即用，浏览器操作） | ✅ P3.5 |
| 9 | 自动任务拆分（远期） | ⬜ 远期 |

### P3.5 — 用户主机 Web 控制台 + 一键启动（方向八·新增）✅

目标：**用户主机上用 UI 操作，调度器保持无界面**。中央调度器部署在服务器上仅提供 gRPC（headless）；用户在自己的电脑上双击 `cpstart`，自动拉起本机 Agent（注册到远程调度器）+ 本地控制台，浏览器打开 `http://127.0.0.1:8080` 先完成**首次配置向导**，随后加入集群，在界面中操作节点 / 作业 / 信任。

**架构定位**：
- 调度器（服务器）：headless，仅 gRPC :9090，**不托管任何 Web 页面**
- 用户主机：`cpstart` 一键启动 → 本机 Agent + 本地控制台（Web UI + REST 桥接，仅监听 `127.0.0.1:8080`）→ 经 gRPC 客户端连接远程调度器

**技术选型**（兼容性优先）：
- 前端：Vue 3 + Vite + Element Plus（静态 SPA，`go:embed` 进 cpstart）
- 本地控制台：`agent/cmd/cpstart` 内嵌 Web 服务 + REST 桥接，复用现有 gRPC 客户端
- 鉴权：本地监听 localhost 免登；远程身份认证与邀请码体系对接（P9）
- 前提：依赖 P2（作业落库）与 P3（调度数据）提供可展示的数据

**任务分解 — A. 本地控制台（Web 界面）**：
- [x] `cpstart` 内嵌 Web 服务（仅监听 `127.0.0.1:8080`，不出网）
- [x] REST/JSON 桥接层：节点 / 作业 / 信任图 / 邀请码 4 组端点（经 gRPC 连远程调度器）
- [x] 前端脚手架（Vue3 + Vite + Element Plus）
- [x] 节点看板：本机及所属节点在线状态 / CPU / 内存 / GPU / 任务数
- [x] 作业管理：yaml 上传提交、列表、详情、取消
- [x] 信任图可视化：节点有向关系图 + 可达路径高亮
- [x] 前端构建产物 `go:embed` 进 cpstart

**任务分解 — B. 一键启动（cpstart，用户主机）**：
- [x] `agent/cmd/cpstart` 入口：无配置启动，读取/生成默认配置（含远程调度器地址）
- [x] 进程编排：拉起本机 Agent（注册到远程调度器）+ 本地控制台
- [x] 自动打开系统默认浏览器 → `http://127.0.0.1:8080`
- [x] Windows：`cpstart.exe` 双击直接运行；console 窗口显示日志
- [x] 优雅退出（Ctrl+C / 托盘图标退出），数据落盘本地

**任务分解 — C. 首次配置向导**：
- [x] 首次启动检测：本地无配置时自动进入向导（配置完成后跳过）
- [x] 向导 1 连接调度器：中央服务器地址 + 端口
- [x] 向导 2 节点身份：节点名称 + 邀请码（与 P9 对接）
- [x] 向导 3 共享资源：CPU 核数 / 内存 / 磁盘 / GPU 选择与配额
- [x] 向导 4 环境检测：containerd / GPU / 调度器连通性检查
- [x] 完成注册：Agent 上线 → 跳转控制台节点看板
- [x] 配置本地持久化，控制台设置页可重进向导
- [x] 验收：用户主机 下载 → 双击 `cpstart` → 打开本地控制台 → 完成首次配置向导 → 加入集群 → 查看节点 + 提交作业（数据经远程调度器）
